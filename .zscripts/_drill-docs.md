## 90. 多人实战演练:多客户端 / 多武器 / 多情况

### 90.1 目的
把测试台从"两个客户端跑通链路"扩成**接近真实开局的演练**:
多个客户端同房对战、逐种武器验证伤害结算、再把容易出问题的边界情况各打一遍。

### 90.2 测试台升级(`scripts/netloop-test.mjs`)
- **N 客户端**:`openTab` 循环建标签页,分队按索引交替(0,1,0,1…);客户端数
  `NETLOOP_CLIENTS`(默认 4)。`pump()` 改为轮流喂前台,客户端越多每轮窗口越短
  (headless 后台标签页 rAF 会掉到 ~0.3fps)。
- **新增相位**:
  | 相位 | 内容 |
  |---|---|
  | `many` | N 客户端同房对战:互相可见 / 记分收敛 / 掉线清理 / 房主停战全房收到 |
  | `drill` | 2 客户端:**武器矩阵** + 同时互杀 / 阵亡不可选 / 复活恢复 |
  | `story` | 剧情合作:中队僚机跨端同步 + **友军免伤**(敌对列表为空)+ AI 位姿一致 |
  | `adversarial` | 剧情对抗:敌我翻转 + **僚机火力真的能打到对端玩家** |

### 90.3 武器矩阵(实测:全部按武器量级正确结算)
做法:用**该武器的实际伤害值**打击远端句柄(`h.hp -= dmg`)—— 与 `weapons.ts` 完全同一条
路径(访问器捕获 → 100ms 合并 → `hit` 事件 → 拥有者扣血 ×0.5 玩家减伤)。

| 武器 | 注入伤害 | 对端实扣 | 期望 |
|---|---|---|---|
| GUN 机炮(20 发 ×4) | 80 | -40 | -40 ✅ |
| MSL 空空导弹 | 120 | -60 | -60 ✅ |
| LASM 反舰/对地 | 180 | -90 | -90 ✅ |
| QAAM 高机动弹 | 100 | -50 | -50 ✅ |
| BDL 炸弹直击 | 200 | -100 | -100 ✅ |

另测**目标链路**:远端玩家进入敌对句柄列表(`hostile=1`), 且点击可选中
(`selectTargetById(handleId)` → `targetInfo().peer === true`, 句柄 id `-2000` 段)。

### 90.4 情况清单(实测)
| 情况 | 结果 |
|---|---|
| 同时互杀(双方同窗口致命伤) | 双方都被击毁、都进复活流程、记分板各 `1 击毁 / 1 被击毁` ✅ |
| 阵亡者不可再被选中 | 双方 `handlesFor(false) = 0` ✅ |
| 复活后重新可见/可打 | 复活成功且对端重新拿到敌对句柄 ✅ |
| 合作模式打不到队友 | 双方敌对列表均为空 ✅ |
| 僚机火力打到对端玩家 | 对端 `hitsReceived ≥ 1` / 掉血 ✅ |
| 4 客户端同房 | 各看到 3 个远端、积分板 4 人、恰一个房主、记分全房收敛 ✅ |
| 掉线清理 | 关掉一个客户端后, 其余客户端看到它的单位被清理 ✅ |
| 房主停战 | 其余客户端都收到 `matchend` ✅ |

### 90.5 演练抓到的**真 bug**(已修):AI 位姿被当成"远端玩家单位"
P5 上线后, 房主的 AI 记录走的是同一条快照通道, 客户端在收包时把**所有**未登记的 hash
都记进 `hash→peer` 表 → 于是 P5 之后客户端会给每架 AI **建出一个幻影远端实体**。
实测症状:`handlesFor(false)` 返回 **7** 个敌对句柄(应为 1 个:对手本人), 于是
"同时互杀"的伤害全打在幻影上, 双方都不掉血; 而因为幻影与对手共用 `peer:<id>` 注册表 id,
**雷达/HUD 的远端数量**在合作模式下恰好没露馅(所以只靠上一轮的断言没发现)。

修法(结构性, 而不是打补丁):**把任务 AI 的 hash 空间与玩家/僚机分离** ——
`hashOfPeer` 清掉最高位(`& 0x7fff`), `aiHash` 置最高位(`0x8000 | …`), 导出
`isAiHash()`。接收端据此**不看表**就能分辨"这条记录是玩家还是 AI":AI 记录只喂插值器、
**绝不进 `hash→peer` 表、绝不建实体**(`registerAiIds` 里也会顺手清掉历史噪声)。

### 90.6 测试侧的坑(已修, 留档)
1. **回血与在途伤害竞争**:测下一种武器前先把血补满, 但上一发的 `hit` 可能还在路上 →
   读数被串到下一项(实测 LASM 显示 0、QAAM 显示 LASM 的伤害)。改为"补血后等 hp 稳定 > 再取基线"。
2. **伤害合并 vs 上限**:同一帧连发 3 次 400 伤害会被发送端**合并成 1 个事件**, 再被 P4 的
   `MAX_HIT_DAMAGE=400` 夹住 → 只扣 200, 杀不死人。致命伤必须**分多次、每次之间留一次刷新窗口**。
3. 复活后对端要收到"存活"快照才重新可见 —— 低帧率下要轮询等待, 不能固定 sleep。
